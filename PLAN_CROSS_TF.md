## ШАГ 3 — Починить 3 дыры Матрицы ✅ ВЫПОЛНЕН 22.10 (см. ниже отчёт)

### Дыра 1: перезапись зон — ПРОВЕРЕНО ФАКТОМ КОДА, формулировка уточнена ✅ ИСПРАВЛЕНО (гибрид A+B)
`zones_plus._publish_cluster` (стр. 302) и `_publish_fvg` (стр. 329) **уже
пишут `tf_sec` в fields** → ось `@ТФ` для зон работает. Настоящая дыра
другая: у зоны две разные зоны на одном ТФ дают одинаковый ключ
`(stop-cluster, zone_low@60)` — `_write` семантически «последнееWins», и
вторая/третья живая зона на той же ступени **затирает первую**. Матрица
хранит «одну правду на поле», а зон на ТФ много.
**Решение (обсудить вариант перед кодом):**
A) адрес через идентификатор зоны: `zone_id` (pkey/born_ts) как
   ось-образующее поле → `zone_low@stop-cluster#<id>`; плюс компактный
   список живых id в отдельной ячейке;
B) зоны пишутся не полем-в-поле, а строкой-значением (dict lo/hi/power),
   key = `zone#<born_ts>@tf` — одна ячейка = одна зона целиком;
C) матрица хранит dict kind→axis→{id: value} (меняется адресная модель).
Тест-сценарий: две кластер-карточки одного tf_sec → обе видимы в срезе.

### Дыра 2: вложенные поля (dict/list схлопываются в одну ячейку) ✅ ИСПРАВЛЕНО
Факт: `_absorb` делает `self._write(kind, axis, value, ...)` для каждого
поля как есть. Если значение — dict (например будущий TE-профиль или
beam со структурой), оно ляжет одной ячейкой и потребитель получит
«коробку», а срезы по осям не построить. При этом докстринг матрицы
обещает «значения хранятся КАК ЕСТЬ, без сплющивания» — противоречие
между обещанием и адресацией.
**Решение (пошагово):**
1. В `_absorb` рекурсивно разворачивать dict в составные оси:
   `axis.sub.subsub` (один уровень вложенности достаточно для текущих
   форматов; глубина ограничена константой MAX_NEST=3, защита от циклов).
2. list/tuple — НЕ разворачивать (это вектор-значение, «как есть»);
   тензорные оси придут естественным путём через dict-поля карточек.
3. Карточки журнала не меняем — разворот только в адресной модели матрицы.
**Критерий приёмки:** unit-прогон: карточка `{"a": {"b": 1}, "c": [..]}` →
ячейки `(k,"a.b")=1`, `(k,"c")=[..]`; обратная совместимость: плоские
карточки дают те же ключи, что раньше.

### Дыра 3: горизонты (forecast затирает forecast) ✅ ИСПРАВЛЕНО
Факт: `regression._publish_fc` пишет `{tf_sec, horizon_min, expect_pct, …}`.
tf_sec попадает в ось, `horizon_min` — нет. Один ТФ с несколькими горизонтами
(или пересчёт того же горизонта с новым значением при том же ts) → одна
полка `trend-forecast/score@tf`. Сейчас каждый скан выдаёт один горизонт на
ступень, но ШАГ 0 (Time Distance) принесёт несколько лагов на ступень —
затирание станет гарантированным.
**Решение:** расширить ключ оси: `axis@tf` → `axis@tf@h{horizon_min}` когда
поле `horizon_min` присутствует (округление до 0.1 мин, стабильный формат).
Реализовать в `_absorb` тем же механизмом, что tf_sec (список «ось-образующих»
полей: `TF_KEYS = ("tf_sec", "horizon_min")`).
**Критерий приёмки:** две карточки fc с одинаковым tf_sec и разными
horizon_min живут двумя разными ячейками; старые записи без horizon_min не
меняют адрес (обратная совместимость для тёплого прогрева из журнала).

Порядок внутри шага: 3 → 2 → 1 (дыра 3 — две строки в `_absorb` и это
precondition для ШАГа 0; дыра 2 — рекурсивный разворот dict; дыра 1 —
самая объёмная, требует выбора адресной схемы A/B/C).
Общий тест-сценарий: синтетический bus-прогон 3 карточек (zone/fc/nested),
проверка keys() матрицы до/после; плюс живой shadow-прогон 10 минут,
сравнение числа ячеек и отсутствия «пропуск устаревшего» в логе.

## ШАГ 0 — Зафиксировать физику кросс-ТФ
Новый аналитик `modules/analyst/cross_tf.py` (или расширение meta_corr —
решить на старте шага):
- **Transfer Entropy** TE(X→Y) по дискретизированным доходностям между
  парами ступеней (1м↔5м, 5м↔15м, …); окно ~200 баров, симметризация
  NET_TE = TE(X→Y) − TE(Y→X).
- **Volatility Concordance**: corr(|r|_fast, |r|_slow) скользящее —
  «совместны ли режимы волатильности».
- **Time Distance**: лаг τ*, максимизирующий TE (кто кого ведёт и на
  каком опережении).
Выход — карточка `cross-tf` с полями `{src_tf, dst_tf, te_net, vc, tau_sec}`.
⚠ После починки дыры 3 эти три числа естественным образом получают ось
`te_net@{src}v{dst}@tau` — потому Шаг 3 и идёт первым.
Фиксация физики = записать метрики в журнал (CARD→keeper) и заморозить
формулы конфигом `[cross_tf]` (bins, window, min_samples).

## ШАГ 5 — Вырезать bias из Сценариста
Факт: writer.py строки ~1115–1242 — ad-hoc сумма ~15 взвешенных знаков
(`magnet_w*trend_term + news_w*mood + rsi_w*rsi_p + …`), часть весов уже
«вырезана» (строка 284). Замена: вместо скалярного bias — **кривая
прогноза** P(Δp | горизонт) из полки ПРОГНОЗ (пересечение лучей регрессии
× TE-ведущие ступени), вердикт = интеграл/экстремум кривой. Это самый
большой шаг по объёму (2059 стр.), разбивается на под-PR: сначала вывод
кривой рядом с bias (теневой дуэт, сравнение в журнале), затем вырезание.
