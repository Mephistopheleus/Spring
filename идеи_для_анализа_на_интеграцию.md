## 2. Система хранения данных — 🔍 К анализу (до этого не разбиралась)

**Текущее состояние (факты, `modules/services/keeper.py`, «Кладовщик»):**
- SQLite `data/neiros.db` (WAL, `synchronous=NORMAL`), лимит 200 МБ
  (`[storage] db_max_mb`). Один писатель в отдельном потоке + очередь 10k;
  чтение — одно соединение под сериализующим замком.
- Таблицы: `cards` (seq/kind/author/confidence/trust/weight/payload-JSON/lineage)
  и `candles` (symbol/tf/OHLCV+delta). Нумерация `MAX(seq)` переживает рестарт.
- Чистка свечей — по квоте: **68 часов истории на таймфрейм, пол 60 баров**
  (`CANDLE_FLOOR_BARS` для Херста/Регрессии). Старое правило «DELETE LIMIT 2000»
  убрано — оно жрало вершину пирамиды (512м) быстрее, чем та копилась.
- **Тик-архив УДАЛЁН (27.10)**: потребителей не было, а сырые сделки стоили
  ~150–190 МБ/сутки при лимите 200 МБ. Замышленная замена — секундные бары
  OHLCV (~2–4 МБ/сутки), **не реализована**.

**Вопросы, требующие анализа (🔍):**
1. Секундные бары: делаем или фиксируем «минуты достаточно»? От этого зависит
   точность контрфакта Лаборатории и Песочницы внутри бара.
2. Одно чтение под общим замком + JSON-payload непрозрачны для индексов:
   фильтрация по значению поля карточки = скан. Вырастет ли это в узкое место,
   когда Метакоррелятор/Интуит начнут тянуть окна глубже?
3. Обратная родословная («кто ссылался на seq X») — только через
   `get_last_cards`; при росте базы нужен ли отдельный индекс по lineage?
4. Целостность и восстановление: WAL + NORMAL дают устойчивость к сбою питания,
   но политики бэкапа `neiros.db` нет (учитывая урок «чумного» backup_29 —
   бэкап должен быть частью процедуры, а не случайным файлом).

## Правила работы с этим файлом
1. Идея из старых диалогов **не становится канон** до ревалидации против
   текущего кода + `ЖУРНАЛ.md` + `BACKLOG.md`.
2. Перед любой реализацией — три вопроса: это новое? это факт? это дубль?
3. Каждый новый вердикт обновляет статус здесь **и** строку в `ЖУРНАЛ.md`
   в тот же день; `BACKLOG.md` получает пункт только для реально открытых задач.
4. ❌-позиции не переоткрываются без новых фактов Лаборатории/контрфакта.
