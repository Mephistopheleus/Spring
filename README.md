# NeirOS-M

Торговый контур для Binance Futures: собирает рынок, строит сценарии,
отдаёт их риск-менеджеру и исполняет — в тени или на бирже.

## Быстрый старт

```
pip install -r requirements.txt
copy config\keys.example.ini config\keys.ini     # Windows
# cp config/keys.example.ini config/keys.ini     # Linux/macOS
python -X utf8 main.py                           # или _start.bat
```

Окно настроек (`config/config.ini`) и эталон сброса
(`config/config.default.ini`) — в комплекте; ключи в `config/keys.ini`
(в систему контроля версий НЕ попадает, см. `.gitignore`).

### Секции ключей

```ini
[keys_testnet]   ; биржа-ТЕСТНЕТ (фантики, песочница)
api_key =
api_secret =

[keys_live]      ; БОЕВАЯ биржа (деньги). Пусто, пока не идёте в бой
api_key =
api_secret =

[keys_news]      ; публичные новостные/макро ключи — опасность нулевая
finnhub_key =
fred_api_key =
newsapi_key =
```

Старый формат (`[binance] testnet_api_key/...`) поддерживается как запасной
путь, но новым считать разделение по контурам.

## Как это устроено

Ядро (`core/`) не знает про модули: оно находит их сами в `modules/`
и запускает по зависимостям (`requires`/`provides`), затем по приоритету.
Модули общаются через шину (`core/bus.py`): конверты с ярлыками, сроком
жизни (TTL) и личные конверты с подтверждением — так команды риск-менеджера
не теряются.

Контур данных:

```
Сборщик → Линзы/Зоны/Поток/OI/RSI/Фракталы/Спринт/Новости/Календарь
        → Анализатор Поля (картина) → Сценарист (сценарии + расписка)
        → Регистратор (карточки с весом) → Риск (allow/shadow)
        → Дилер (исполнение) → Склад (история) → Тюнер (доверия и ручки)
```

Правило проекта: прогноз без «расписки» в систему не входит; доверенные
данные проверяются Лабораторией по факту, а не верят на слово.

## Торговля: контуры и режимы

Два контура, жёстко разделённые. Ключи лежат в РАЗНЫХ секциях `keys.ini`,
и система **не выбирает биржу сама** по наличию ключей — только явная ручка.
Третьих состояний нет (прежний `contour = shadow` и режим `lab` вырезаны).

| Ручка в `config.ini` | Значения | Смысл |
|---|---|---|
| `[trading] contour` | `testnet` \| `live` | какая биржа используется |
| `[trading] testnet_mode` | `real` \| `shadow` | режим тестнета (фантики) |
| `[trading] live_mode` | `real` \| `shadow` | режим боевой биржи (деньги) |
| `[trading] live_enabled` | `true` \| `false` | рубильник **только** боевого контура |

Режимы одного контура — ровно два:

- **real** — ордера реально идут на биржу этого контура (в testnet это фантики);
- **shadow** — сделка просчитывается на бумаге, ордер не уходит.

Матрица хозяина (других сочетаний не бывает):

| Контур | Режим | Что делает |
|---|---|---|
| `testnet` | `real` | ордера на тестнете (фантики); рубильник не важен |
| `testnet` | `shadow` | только симуляция |
| `live` | `real` | ордера на боевой бирже; **требует `live_enabled = true`** |
| `live` | `shadow` | только симуляция; рубильник не важен |

Мусор в значении не создаёт третьего состояния: `contour` схлопывается в
безопасный `testnet`, неизвестный режим — в `shadow`.

### Что делает рубильник

`live_enabled` отвечает **только за LIVE-контур (деньги)**:

- `live_mode = real` + `live_enabled = false` → боевой реал **заблокирован**, работаем в тени;
- `live_mode = real` + `live_enabled = true` → боевой реал разрешён;
- на **testnet-реал рубильник не влияет** — песочница гоняется свободно
  (иначе нельзя было бы тестировать робота на фантиках).

Итоговый режим всегда виден в журнале при старте:

```
Контур TESTNET, режим REAL (ТЕСТНЕТ, фантики): баланс старта 3309.72 USDT
```

Готовые сочетания под типовые задачи:

| Задача | contour | testnet_mode | live_mode | live_enabled |
|---|---|---|---|---|
| тест робота в песочнице | `testnet` | `real` | `shadow` | `false` |
| только замеры, без сделок | `testnet` | `lab` | `shadow` | `false` |
| бумажная торговля без биржи | `shadow` | — | — | `false` |
| боевой запуск (деньги) | `live` | — | `real` | **`true`** |

### Защита позиции
Hedge-режим, изолированная маржа, биржевой STOP-MARKET сразу после входа,
идемпотентные `newClientOrderId` (повтор с тем же id биржа отвергнет как
дубликат, а не откроет вторую позицию).

Диагностика ключей и контуров: `python -X utf8 _key_check.py [testnet|live]`.

## Проверки

```
python tests\run_all.py              # офлайн-проверки (без сети)
python tests\run_all.py --live       # + проверки, нуждающиеся сети/биржи
python tests\run_all.py --only smoke_core,smoke_stage36
```

Каждая проверка — самостоятельный скрипт `tests/smoke_stage*.py`.
`--live` включает `smoke_stage19` — он открывает реальную сделку на
тестнете; без ключей его запускать бессмысленно.

## Настройки

Всё, что режет или усиливает данные, живёт в `config/config.ini`.
`config/config.default.ini` — эталон полного сброса: скопируйте его на
`config.ini`, если хотите начать с утверждённых стартов.

Полный сброс (по решению хозяина):

1. `copy config\config.default.ini config\config.ini`
2. удалить файл базы Тюнера (рядом со Складом: `data/neiros.base`) — учёт заново;
3. `data/neiros.db` чистить по желанию (история сделок).

## Структура

```
core/       ядро: kernel, bus, config, discovery, module, logging_setup
modules/    боевые модули (market, analyst, scenario, trading, services, ui)
ui/         экран-мини-терминал (Qt, свой поток)
tests/      проверки (smoke_stage*.py) и единый раннер run_all.py
tools/      разовые аналитические скрипты (не часть системы)
config/     config.ini (рабочий), config.default.ini (эталон), keys.ini (секреты)
data/       база (SQLite) и база Тюнера
logs/       журнал с ротацией
BACKLOG.md  решения и бэклог; audit_plan_fact.md — план против факта
```

## Экран

Модуль `screen` (мини-терминал: свечи, цена, здоровье модулей) включается
ручкой `[ui] enabled = true` и требует PyQt5/matplotlib. По умолчанию
выключен — на сервере без Qt он падал бы на старте.
